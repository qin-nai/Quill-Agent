# Quill Agent WebUI 设计

移动端 AI 编程代理界面。目标:同一套 UI 同时适配手机与平板,卡片随分辨率缩放,
整体留出富裕的呼吸空间,用户不读手册就能看懂每个按钮。

## 1. 设计定位

- **产品**:开发者用的移动端 AI 编程代理(类 Claude Code)
- **风格**:Quiet Pro —— 现代克制的开发者工具。内容优先、卡片化、深色默认 + 浅色可切。
  参考观感:Warp / Claude Code / Linear。不做玻璃拟态、不做渐变堆砌、不用 emoji 当图标。
- **第一屏重点**:让用户立刻明白"这是和 AI 的对话界面",主操作只有一件(发送)。

## 2. 设计系统

### 2.1 色彩(语义 token,深/浅两套)

| Token | Dark | Light | 用途 |
|---|---|---|---|
| `--bg` | `#0C0E12` | `#FAFAF8` | 页面底色 |
| `--surface` | `#14171C` | `#FFFFFF` | 卡片 |
| `--surface-2` | `#1B2027` | `#F5F4F1` | 输入区/嵌套卡片 |
| `--border` | `#262B33` | `#E5E4E0` | 分隔线/描边 |
| `--text` | `#E6E8EB` | `#1A1C20` | 正文 |
| `--muted` | `#8A919C` | `#6B7280` | 次要文字 |
| `--faint` | `#5C6470` | `#9CA3AF` | 占位/禁用 |
| `--accent` | `#E07B54` | `#C4522B` | **唯一强调色**:主操作/助手身份 |
| `--on-accent` | `#1A110B` | `#FFFFFF` | 强调色上的文字 |
| `--danger` | `#EF5350` | `#D9382F` | 错误/拒绝 |
| `--success` | `#3FBF7F` | `#2E9E63` | 成功 |

原则:
- 强调色只用于一处(当前主 CTA / 选中态 / 助手标记),不铺开。
- 功能性颜色(错误/成功)**永远配图标或文字**,不单独用颜色表意。
- 分隔线要够得着(深色里 `#262B33` 可见,浅色里 `#E5E4E0` 可见)。

### 2.2 排版

- 字体:系统栈 `-apple-system, "Segoe UI", Roboto, "PingFang SC", "Microsoft YaHei", sans-serif`;
  代码/标识符用 `ui-monospace, "Cascadia Code", Consolas, monospace`。
- 字号:12 注释 / 14 次要 / **16 正文(下限,防 iOS 输入自动缩放)** / 18 卡片标题 / 22 页面标题 / 28 空状态大标题。
- 行高:正文 1.5~1.6;代码 1.5。
- 行宽:消息正文 ≤ 65ch(平板不铺满,保可读)。

### 2.3 间距(4/8 节奏,重点:留白)

| 层级 | 值 |
|---|---|
| 页面边距 | `clamp(16px, 4vw, 32px)` |
| 卡片内边距 | `clamp(14px, 3vw, 24px)` |
| 消息之间 | 16~24px |
| 区块之间 | 24 / 32 / 48px |

规则:内容不贴边、卡片不挤在一起;同层级间距一致(4/8 节奏)。

### 2.4 圆角 / 投影 / 图标

- 圆角:卡片 16、按钮 12、chip 999(胶囊)、输入 12、代码块 10。
- 投影克制:层级靠 1px 边框区分;只有弹窗/抽屉/底部 sheet 用柔和阴影(模拟浮层)。
- 图标:统一 Lucide 风格线稿 SVG,`stroke-width: 1.75`,**不用 emoji**。
  图标尺寸 token:16 / 18 / 20 / 24。同一层级用同一 stroke 粗细。

## 3. 响应式(手机 / 平板)

断点:**640**(手机↔平板)、**1024**(大平板横屏)。设计从手机起,再放大到平板。

### 3.1 手机(<640)

- 单列。顶栏:汉堡(开会话抽屉)、标题、当前模型 chip。
- 底部固定输入栏(贴安全区):附件图标 + 输入框 + 发送/停止按钮。
- 会话列表、文件树、设置 → 左侧滑出抽屉。
- 确认弹窗 → 底部 sheet(拇指自然可达)。
- 工具调用卡片默认收起,只显示"图标 + 工具名 + 状态",点开看参数。

### 3.2 平板(≥640)

- 左侧会话栏(280px,可收起为 64px 图标栏)+ 右侧对话区。主操作不变。
- 文件树右侧抽屉;确认弹窗 → 居中对话框(不再是底部 sheet)。
- 会话卡片、文件条目用 `grid repeat(auto-fill, minmax(...))`,宽度变大自动增列。

### 3.3 卡片缩放(不同分辨率通用规则)

- **不写死 px 宽**:卡片 `width:100%` + `max-width` 上限;字体/间距用 `clamp()`。
- grid 用 `repeat(auto-fill, minmax(140px, 1fr))` 之类,大屏自动多列,小屏单列。
- 消息气泡 `max-width: 640px`,平板/横屏居中不铺满。
- 顶栏、输入栏等固定元素为 `min-h-dvh` 服务,内容区留出安全区高度。

## 4. 自解释 UX 原则(不读手册就懂)

1. **主操作唯一且显眼**:每屏只有一个主 CTA。对话页 = 发送(填充强调色圆钮);
   其余操作全部次级样式(描边/幽灵按钮)。
2. **图标按钮必须配文字或 aria-label**:图标只做辅助,不单独表意。
   例如"附件"用回形针图标 + `aria-label="添加附件"`;危险操作写全词"删除"。
3. **工具调用透明化**:每条工具调用是一个卡片,`图标 + 工具名 + 状态`
   (运行中=脉冲点、成功=绿勾、失败=红+错误原因)。用户随时知道 agent 在干什么、
   为什么慢。参数展开看,不让原始 JSON 糊脸。
4. **确认弹窗说人话**:不用 approve/deny。标题写"写入文件",正文用大白话描述
   "将覆盖 src/main.cpp"(附 diff 预览),按钮写 **"允许"** / **"拒绝"**。
   拒绝理由可留白输入,给 agent 回头路。
5. **空状态给行动**:如"还没有会话" + 一个大的"新建会话"按钮,而不是空白屏。
6. **流式输出逐字显示**,生成中顶部出现"停止"按钮(红色系),结束后自动消失。
7. **每个操作有反馈**:按钮按下 80-150ms 内出现按压态;提交中按钮转 spinner 并禁用。
8. **触碰目标 ≥44×44**,图标小就用 hit-area 外扩。
9. **状态不靠颜色单独表意**:错误/成功都带图标或文字。
10. **方向不变式**:底部导航/输入栏位置在手机与平板一致,不因分辨率跳位。

## 5. 页面与组件清单

| 组件 | 关键点 |
|---|---|
| 顶栏 | 汉堡(手机)、标题、模型 chip(可点开设置)、更多按钮 |
| 会话列表(侧栏/抽屉) | 每项:标题 + 模型 + 更新时间;当前会话高亮;底部"新建会话"大按钮 |
| 消息流 | 用户=右侧气泡;助手=左侧卡片;工具调用=折叠卡片;流式文本逐字追加 |
| 输入栏 | 附件(回形针)+ 自适应 textarea + 发送/停止;输入中按需增行 |
| 确认弹窗 | 手机底部 sheet / 平板居中;人话描述 + 预览 + 允许/拒绝/拒绝理由 |
| 文件树(抽屉) | 懒加载目录;点击文件只读预览;不做编辑(编辑走对话) |
| 设置 | provider 下拉 + 模型 + API key(明文/遮蔽切换)+ 测试连接 + 深/浅色切换 |

## 6. 反模式(明确不做)

- emoji 当图标、随机圆角/投影、多处强调色
- 图标-only 且无 aria-label 的按钮
- 固定 px 宽度的卡片(不随分辨率缩放)
- 全宽长文本(平板下无行宽限制)
- 弹窗里直接甩原始 JSON 参数让用户判读
- 纯颜色表达错误/成功,无图标文字伴随
